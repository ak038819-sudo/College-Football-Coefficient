# Production-readiness review — The Modern team pages

**Approval state: NOT YET APPROVED FOR PRODUCTION.** This document is a
release gate, not a release announcement. PR #161 must remain draft.

## The screenshot's actual content is non-negotiable

The mobile BYU screenshot reveals a dense hero with team identity, follow
button, conference/season, linked stadium and coach, Elo, Season Merits,
Legacy Merits (5-year) and W–L record, followed by eight existing sub-tabs.
The Modern styling is applied to this **real team header**, not an alternate
team renderer. The real data is still generated by the existing backend.
The routing and sub-tab code has not been removed or replaced.

## Implemented in the actual dashboard build

- `ui/team-modern.css`: scoped dark sapphire hero, atmospheric abstract
  mountain accents, readable number cards, compact responsive two-column
  KPIs at phone width, mobile-friendly horizontally scrollable tab row.
  Source-controlled, no image-network requirement.
- `build_dashboard.py`: requires the stylesheet during a dashboard build,
  hashes the asset and injects a versioned stylesheet link so installed-app
  caches invalidate after design edits.
- `tests/test_team_modern_integration.py`: protects existing team-header
  values and all eight tabs and checks the stylesheet build linkage.
- Separate `ui/prototypes/modern-team-profile.html` is a **design demo**
  only and must not be mistaken for the deployed page.
- The validated `elocast-descriptive-v1` contract is ready for a subsequent
  stats-card integration; **the new radar visualization is not yet wired
  into team landing routes**. Never show the concept's invented BYU numbers.

## Required verification before merge / publish

1. **CI:** Full GitHub Actions Python+Node tests, database bootstrap,
   generated dashboard build, and `git diff --check` all green at the
   final commit.
2. **Actual iPhone/Android/browser visual review:** phone widths around
   375px, 390px, 430px, tablet 768px and desktop 1280px. Check wrap,
   vertical rhythm, notch/safe areas, horizontal scrolling only within
   the team tab strip, and color contrast in both dark and system-light
   modes. This needs a true browser screenshot review; fixture/source
   tests alone cannot certify it.
3. **Behavior:** Route to team from Teams, search, rankings and live game;
   browser Back; team follow toggle; coach and stadium links; Elo freshness,
   season history and conference links.
4. **Content:** Elo, Merits season, Legacy Merits, record, rank change, and
   non-FBS record caveat must match the original canonical source exactly.
   Missing fields remain N/A; no invented percentages.
5. **Eight tabs:** Overview, This Week, Schedule, Roster, Stats, Leaders,
   History, Analytics. Check tab URL round-tripping, late-loaded player
   profiles, season chooser, mobile tables and swipe/horizontal tables.
6. **Scouting integration:** Once the design review passes, separately
   integrate static, source-verified `elocast-descriptive-v1` metrics,
   guard unavailable data and test reliable offline/PWA caching. The
   experimental predictive matchup JSON is not a substitute.
7. **Data release:** Review whether to promote archived research CFBD
   splits into the standard static-export pipeline, then verify
   distribution size and cache behavior without breaking live builds.

## Release decision

The first live-renderer styling pass may advance to QA, but until the
above checks and scouting integration complete, **this is not a
production-ready full team-page overhaul**. Do not merge, deploy or remove
the draft flag without user authorization.
